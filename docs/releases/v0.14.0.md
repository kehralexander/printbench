# PrintBench v0.14.0

PrintBench 0.14.0 lets you change the spool in a KX-Bridge printer's slot from
PrintBench. One step updates the printer, KX-Bridge and Spoolman. Shown slot
contents are also more reliable: a spool is no longer reported as loaded after
it has been swapped out.

## Highlights

### Change a slot's spool in one place

- **A Change link on each KX-Bridge slot** on the printers page opens a dialog.
  Pick the spool going in and where the one coming out should go. PrintBench
  then sets the printer's slot material and colour, the bridge's slicer
  profile and spool binding, and both spools' locations in Spoolman. Finally
  it reads the slot back to confirm.
- Every step can be repeated, so if one fails, running the change again
  finishes it. Nothing is rolled back.
- A change is refused while the printer is busy, because rebinding a slot
  resets the bridge's usage counters.
- **Load a spool from where you notice it is missing.** A queue row's
  "not loaded" line offers **Load #N** for each missing Spoolman spool. Each
  spool in the Spoolman inventory offers **Load into <printer>**. Both open
  the same dialog for the first idle KX-Bridge printer, with the spool already
  picked, and ask which slot it goes in.

### Slot contents you can trust

- **A slot's spool binding only counts while the slot agrees with it.** The
  bridge can keep reporting a Spoolman spool in a slot after it was swapped
  out. Before, a request for a yellow spool could show as loaded in a slot
  holding white, and sending would pick that slot. A binding now only counts
  while the slot's material and colour match the spool.
- **Colours reported by the printer no longer hide a correct binding.**
  Printers report a slot's colour from their own palette, which can be far
  from the spool's real colour. A bound spool is now only treated as missing
  when the colours are clearly different.
- Slots whose bound spool clearly does not match what they report are marked.

### Queue

- **Send & start… and Link to library… stay open** when opened from a queue
  row's menu. Before, they closed again as soon as they opened.

### Spoolman connection

- **`SPOOLMAN_PUBLIC_URL`** sets the address used for "open in Spoolman"
  links. `SPOOLMAN_URL` can then be an internal address, such as a Compose
  container name or a Kubernetes service. The server reaches Spoolman directly
  instead of going through the reverse proxy and external DNS.
- When Spoolman cannot be reached, the log warning now gives the underlying
  network error (for example `ECONNRESET` or `ENOTFOUND`) instead of a bare
  "fetch failed".

## Upgrade notes

- **No database migration and no backup-format change.**
- **`SPOOLMAN_PUBLIC_URL` is new and optional.** Without it, links fall back
  to `SPOOLMAN_URL`, as before. No action is needed unless you want to point
  `SPOOLMAN_URL` at an internal address. See
  [Deployment → Spoolman](../deployment.md#spoolman).
- **PrintBench now writes to Spoolman.** It only does so when you change a
  slot's spool, and only sets the location of the spools involved. Spoolman
  creates a location the first time a spool names it. If Spoolman sits behind
  a proxy that only allows reads, allow `PATCH` requests to
  `/api/v1/spool/<id>`, or spool changes will report that Spoolman could not
  be updated.
- If upgrading from an earlier version, also read the
  [v0.13.0 upgrade notes](v0.13.0.md) and the earlier release notes linked
  there.
