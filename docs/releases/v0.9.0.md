# PrintBench v0.9.0

PrintBench 0.9.0 adds requests with more than one filament, and pricing:
what a print costs you, what you charge for it, quotes the requester can
accept, payments and invoices. It also brings in upstream PrintBench v0.7.5.

## Highlights

### Multi-filament requests

- **One filament per tool.** A request lists a material, colour and spool for
  each tool it prints with. Linking a sliced file fills the list in from the
  G-code, including each tool's grams, and only counts the tools that the
  file actually uses. A single-filament request looks the same as before.
- **The queue checks every colour.** A request is ready only when all of its
  filaments are loaded on one printer, and the "not loaded" badge says which
  colour is missing. The "load next" hint and the spool forecast add up grams
  per spool across all of a request's filaments.
- **KX-Bridge puts each tool on its slot** using that tool's spool, or else its
  colour and material.
- **Print history records each filament.** When a print finishes, the usage
  for every filament on a local spool is written to the history.
- Queue rows and the requester's status page show one swatch per colour.

### Pricing

Pricing is off until it is switched on under Manage → System settings → Pricing.

- **Cost per print** includes:
  - material: grams × price per gram, taken from the local spool, else
    Spoolman's spool or filament price, else a per-material default;
  - electricity and machine time, from each printer's power and hourly rate
    (Manage → Printers) or the defaults;
  - a failure allowance, based on the success rate from print history.
- **Price** comes from tiers. Each tier has a markup, a handling fee per
  request and a minimum. A request uses its customer's default tier unless
  you pick another one. Prices can be rounded, and you can type a manual
  price that is never recalculated.
- **Quotes.** Quote a request from its editor. The requester sees the price
  and can accept or decline it on their status page, optionally with a rough
  breakdown.
  - Quotes expire after a set number of days.
  - Changing the file, quantity, colours or tier after quoting marks the
    request "quote again" instead of silently changing the price.
  - Optionally, quoted requests are held back from printing until they are
    accepted, and a deposit can be required above a set price.
- **Payments and customers.** Record payments by cash, bank transfer, PayPal
  or other, including deposits, partial payments and refunds. Named customers
  have a default tier. The new **Billing** page shows open balances per
  customer, the customer list and invoices.
- **Invoices and receipts.** Each invoice is a PDF with a gap-free number,
  your name, address and payment details. The tax setting chooses between:
  - no tax line;
  - the German small-business note (§19 UStG);
  - VAT at a set rate, included in the quoted price.

  Invoices are never deleted.

- **What it actually cost.** After printing, the request's real cost from its
  print runs is shown next to the quoted cost.
- **The model page** shows "≈ €… to print" for models with a G-code file.
- Billing needs the new `billing:manage` permission, which members and admins
  have. Viewers never see costs or quote controls.

### From upstream v0.7.5

- Model details show the primary source in the Source field and additional
  original model pages under Additional Links.
- Updates to Next.js 16.4.5, Better Auth 1.7.17, Three.js 0.187.0, Chokidar
  6.0.0 and other dependencies. See the [v0.7.5 notes](v0.7.5.md).
- The web app and the auth package use the same Better Auth version again, and
  the container image build no longer fails to find it.

## Upgrade notes

- **Back up first.** The normal deployment migration flow applies migration
  `0024_multi_filament_pricing`. It adds the `print_request_filaments`,
  `customers`, `request_payments` and `invoices` tables, as well as pricing
  columns on `print_requests` and `print_hosts`.
- **The migration moves request filaments.** Each request's material, colour,
  Spoolman spool and filament weight are copied into one
  `print_request_filaments` row. The old columns on `print_requests` are then
  dropped. Requests that named no filament get no row, which still means "any
  filament". Anything that reads those columns directly from the database,
  such as your own scripts or reports, has to read the new table instead.
- **This release is forward-only.** Going back to 0.8.x requires the database
  backup from before the upgrade. A 0.9.0 backup cannot be restored into
  0.8.x. Older backups still restore into 0.9.0 and are migrated forward.
- **The new tables are part of backups.** Manage → Backup and `pg_dump`
  include them automatically, so there is nothing to configure.
- No environment variables were added or changed. All pricing settings are
  stored in the database, and nothing changes until pricing is switched on.
- **Status links can now accept or decline a quote.** With pricing on,
  requesters can use `/r/<token>` to accept or decline a quote. They still
  need no account and see nothing beyond their own request.
- Source installations should run `npm ci` and rebuild both the web app and
  worker. No new dependencies are needed: the PDF writer is built in.
- If upgrading from an earlier version, also read the
  [v0.8.2 upgrade notes](v0.8.2.md) and the earlier release notes linked there.
