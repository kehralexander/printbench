# PrintBench v0.10.0

PrintBench 0.10.0 lets you rename the files inside a model.

## Highlights

### Renaming files

- **A pencil on every file row.** On a model page, the name turns into a
  field: Enter saves, Escape cancels. It is shown to members and admins, and
  only for libraries PrintBench may write to — managed libraries, and in-place
  libraries with writes enabled.
- **The file stays the same file.** It is renamed on disk or in S3 and in the
  database in one step, so the next scan finds a file it already knows. Its
  print history, request links and the model's preview choice all stay with
  it, and the new name is searchable straight away.
- **Single-file models** are renamed along with their file.
- **Only the name changes.** The file stays in its folder and keeps its
  extension, since the extension decides its type and thumbnail. Names that
  are already taken in that folder, names library scans skip (such as
  dotfiles), and, for single-file models, a name another model or the
  removed-models list already uses are refused with a message saying why.
- Each rename is recorded in the audit log with the old and new name.

## Upgrade notes

- No additional upgrade action is needed when upgrading from v0.9.0. This
  release adds no database migrations, environment changes or backup-format
  changes. Follow the normal backup and container upgrade procedure.
- In-place libraries stay read-only unless writes were explicitly enabled for
  them; renaming does not change that.
- If upgrading from an earlier version, also read the
  [v0.9.0 upgrade notes](v0.9.0.md) and the earlier release notes linked there.
