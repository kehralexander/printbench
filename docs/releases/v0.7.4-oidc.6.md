# PrintBench v0.7.4-oidc.6

Fork build of PrintBench 0.7.4 (OIDC sign-in, adding files to models, G-code
previews, print-queue details, Spoolman inventory, printer status) where the
printers now drive the queue and the print history.

## Highlights

- **Printers are watched.** The worker reads every configured printer every
  20 seconds and follows each job from start to finish, whether it was started
  from PrintBench, the slicer or the printer itself.
- **The queue follows the printer.** When a printer starts a file that a queued
  request is waiting for, the request goes on the printer with the real start
  time. When the job ends it counts a print. Requests for several copies show
  "1 of 3 printed" and wait for the next one, and close once all are done. A
  cancelled or failed print sends the request back to waiting. A request
  someone already marked as printing, or sent with Send & start, is matched
  first.
- **Prints are logged automatically.** Every finished job whose file is in
  the library is added to the print history with the printer, real start and
  end times, duration and, for a successful print, the filament weight from the
  G-code. Cancelled and failed prints are logged as failed with how far they
  got ("Cancelled on Kobra X at 40%"). These real durations feed the queue's
  estimate suggestions. A request marked printed by hand while it was still
  printing gets the printer's times instead of a second entry.
- **Live times in the queue.** A request on a watched printer shows "On Kobra
  X · 32% · done around 14:35, then 1 more". The queue total counts what the
  printer says is left of the running print, and the header says when
  everything should be done.
- **Send & start from the queue.** A waiting request with a sliced file has a
  Send & start button. It checks the printer is free, uploads the file, starts
  the print and puts the request on the printer.
- **Loaded filament.** The status page shows the slots of a multi-material
  unit (an Anycubic ACE through KX-Bridge, or a Happy Hare MMU): colour,
  material, the slot in use and its Spoolman spool. Waiting requests say
  "Loaded on Kobra X, slot 2", or "Not loaded" next to what is loaded instead.
  A request with a Spoolman spool is matched by spool ID; otherwise by material
  family and colour.

## Upgrade notes

- One migration (`0020_printer_tracking`) adds the `printer_jobs` table, the
  last status snapshot on `print_hosts`, and `prints_done` and
  `printer_job_id` on `print_requests`. It is dated directly after the
  previous fork migration.
- The worker now needs network access to the printers, as the web app already
  did. `PRINTER_POLL_SECONDS` sets the interval (default 20); `0` turns
  watching off.
- Run a single worker. Two workers would each record the same jobs.
- Only jobs that start after the upgrade are tracked; earlier printer history
  is not imported.
