# PrintBench v0.8.0

PrintBench 0.8.0 brings single sign-on, a print queue that follows the
printers, Spoolman as the filament inventory, a live printer status page and a
consistent design across every page. It collects the `v0.7.4-oidc.1` to
`v0.7.4-oidc.13` prereleases into one stable release.

## Highlights

### Sign-in

- **OpenID Connect single sign-on** with any provider (Authentik, Keycloak, …).
  The login page shows "Sign in with <name>" when SSO is configured. An SSO
  sign-in attaches to the existing account with the same email, so current
  users keep their role and libraries.
- **Auto-provisioning.** With `OIDC_ALLOW_SIGNUP=true`, accounts are created on
  the first SSO sign-in, with a role from the provider's groups claim:
  `OIDC_ADMIN_GROUPS` and `OIDC_MEMBER_GROUPS` map groups to roles, anyone else
  is a viewer, and `OIDC_ALLOWED_GROUPS` refuses anyone in none of the listed
  groups with a clear message. `OIDC_GROUPS_CLAIM` names the claim (`groups` by
  default). The role is re-applied on every sign-in for accounts that only use
  SSO; accounts with a password keep the role set in PrintBench. New accounts
  take their name and email from the provider. Sign-ins, provisioning, role
  changes and refusals are recorded in the audit log.
- **SSO-only sign-in.** Admins can hide the email and password fields on the
  sign-in page. `/login?password=1` still shows them.

### Library

- **One Models page.** Browsing and searching are the same page: search box,
  sort and filters above the grid, and an empty search is the whole library
  A–Z. Paging steps by cursor in every order except best match, so a page deep
  into a large library costs no more than the first, and thumbnails, formats
  and dimensions are looked up for the page only (about 80 ms to 6 ms per page
  on a 20,000-model library).
- **Add files to a model.** Members can upload more meshes, G-code, images,
  documents or a ZIP straight into a model's folder. Nothing is ever replaced:
  a clashing name is stored as `name (1).ext`. A single-file model is first
  moved into its own folder after confirmation and keeps its id, tags, notes,
  history, collections and share links.
- **G-code previews.** The preview image that PrusaSlicer, SuperSlicer, Orca
  and Cura embed in `.gcode`, and the thumbnails in Prusa `.bgcode`, become the
  file's thumbnail and stand in as the model's preview when nothing else
  rendered.

### Print queue

- **Richer requests.** Every open request can be edited: wording, quantity,
  priority, due date, requester, notes, material and colour, the file or plate
  to print, and the print time. Estimates are typed as "2h 10m", "2:10" or
  minutes and suggested from the slicer, the model's G-code or earlier prints;
  the queue shows the total ("~14h of printing") and when everything should be
  done.
- **The queue follows the printers.** The worker watches every printer and
  follows each job however it was started. A request goes on the printer when
  its file starts, counts a print when the job ends ("1 of 3 printed"), closes
  when all are done, and goes back to waiting after a cancel or failure. Live
  rows show "On Kobra X · 32% · done around 14:35".
- **Send & start** uploads a request's sliced file and starts it on a free
  printer.
- **What to print next.** An idle printer's suggestion uses the filament it has
  loaded ("Ready to start: Benchy for Sam (slot 2)"), or says what to load for
  the most urgent request.
- **Drag to reorder.** Give the open queue a manual order by dragging or with
  the arrow keys; it also decides which request a started file belongs to.
  "Reset order" goes back to priority, due date and age.
- **Status links for requesters.** Every request has a link and QR code that
  needs no account, showing its place in the queue, a likely ready time, live
  progress while it prints, and the model's picture.

### Printers

- **Printer status page** and dashboard cards: idle or busy, the file,
  progress, elapsed and remaining time, "done around", layer and temperatures,
  ticking every second between refreshes. Moonraker (including KX-Bridge's own
  countdown), OctoPrint and PrusaLink are supported. A printer that does not
  answer within 5 s shows as offline without slowing the page down.
- **Loaded filament.** The slots of a multi-material unit (Anycubic ACE through
  KX-Bridge, Happy Hare MMU) with colour, material and Spoolman spool. Waiting
  requests say whether their filament is loaded.
- **KX-Bridge printer type.** "Send & start" names the ACE slot to print from:
  the request's spool, else its material and colour, else the colours each tool
  was sliced with. When it is not clear, you choose before anything is sent.
- **Warm-ups are not cancels.** A printer that goes quiet without saying how
  the job ended keeps its job open for three minutes, so heating and levelling
  no longer show up as "Cancelled at 0%".

### Print history

- **Logged automatically.** Every finished job whose file is in the library is
  added to the print history with printer, real times, duration and filament
  weight. Cancelled and failed prints say how far they got.
- **How did it go?** Printer-logged prints can be rated with one click from the
  dashboard or the history, with an optional note or photo.
- **Jobs not in the library** can be linked to a model (writing the history
  after the fact), fetched from the printer into a model's folder, or
  dismissed. Files that turn up later are linked on their own.
- **Success rates** by model, file and material, with where failed prints
  usually stop and a hint at why.

### Filament

- **Spoolman as the inventory.** Set `SPOOLMAN_URL` and Spoolman owns spools
  and stock; PrintBench only reads from it. The Filaments page lists its spools,
  the queue's picker offers them, requests show what is left ("Spool #17 ·
  894 g left"), and the queue warns when a spool will run out before everything
  queued on it is printed. When Spoolman is unreachable, pages say so and keep
  working.

### Everywhere

- **One design system.** Editing happens in dialogs with Cancel and the action
  on the right; every list sorts with the same control; swatches, stat tiles,
  tables, badges, empty states, headers and dialogs look alike in light and
  dark mode and on phones. Dates read "1 Nov 2026", durations "6h 52m", and
  destructive actions are red.
- **Pages keep themselves up to date** while something is happening: after a
  scan, health check or model processing finishes, while previews are being
  made, and while a print is running.
- Fixes: times show in the browser's timezone; a tag, creator or library filter
  that is not an id no longer breaks the Models page; unknown addresses get a
  themed "Nothing here" page; server logs are listed in the order they were
  written.

## Upgrade notes

- **Back up first.** The normal deployment migration flow applies six
  migrations, `0018_queue_details` through `0023_printer_job_idle`. They add columns to `print_requests`,
  `print_hosts`, `print_runs` and `printer_jobs`, the `printer_jobs` table and
  the `kx-bridge` printer type. They are additive and safe on a running
  database, but forward-only: going back to 0.7.x needs the database backup.
- **Upgrading from a `v0.7.4-oidc.*` build:** only the migrations you do not
  have yet run, and no action is needed beyond the normal container upgrade.
- **All new settings are optional**; without them PrintBench behaves as 0.7.4:
  - SSO: `OIDC_ISSUER`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`, and optionally
    `OIDC_NAME`, `OIDC_ALLOW_SIGNUP`, `OIDC_ADMIN_GROUPS`,
    `OIDC_MEMBER_GROUPS`, `OIDC_ALLOWED_GROUPS` and `OIDC_GROUPS_CLAIM`.
    Register `<BETTER_AUTH_URL>/api/auth/callback/oidc` as the redirect URI
    with scopes `openid email profile`, and have the provider put the groups
    in the ID token or userinfo.
  - Spoolman: `SPOOLMAN_URL`, for example `http://spoolman:7912`. While it is
    set, the built-in spool pages are disabled; their data is kept and returns
    when it is removed.
  - Printer watching: `PRINTER_POLL_SECONDS` (default 20, `0` turns it off).
- **The worker now talks to the printers.** Give it network access to them, as
  the web app already had, and run a single worker: two would record every job
  twice. Only jobs that start after the upgrade are tracked.
- **Print photos** are stored under `DATA_DIR/photos`. Keep that directory on
  the persistent volume and in backups, like the previews.
- **Status links** (`/r/<token>`, its QR code and the model's thumbnail) are
  served without a session. They show one request and nothing else. The QR code
  encodes `BETTER_AUTH_URL` (or `APP_URL`) when set.
- To use slot choice on an Anycubic Kobra X, change the printer's type to
  "KX-Bridge" under Manage → Printers. It needs KX-Bridge 0.9.x.
- Old `/search` links redirect to `/models` with the same query.
- Source installations should run `npm ci` (new dependency: `qrcode`) and
  rebuild both the web app and worker.
- If upgrading from earlier than 0.7.4, also read the
  [v0.7.4 upgrade notes](v0.7.4.md) and the earlier notes linked there.
